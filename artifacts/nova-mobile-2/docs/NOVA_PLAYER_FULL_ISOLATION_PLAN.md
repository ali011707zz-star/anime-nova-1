# خطة: التحوّل الكامل لمشغّل معزول حقيقياً (عملية Android منفصلة داخل نفس التطبيق)

**الحالة:** القرار النهائي اتُّخذ بتاريخ 2026-08-06 (راجع "القرار النهائي المُحدَّث" أدناه).
لم يبدأ التنفيذ الفعلي بعد — هذه الخطة تحدّد الاتجاه المعماري ليُنفَّذه عمل مخصّص لاحقاً.

## القرار النهائي المُحدَّث (2026-08-06)

بعد نقاش، **رفضنا خيار الاعتماد على تطبيق NOVA Player الخارجي الجاهز** (القسم الأصلي
أدناه) لأنه يفقد ميزات حقيقية (الترجمة الذكية، تخطي المقدمة/الخاتمة) ولا نملك
كوده. القرار النهائي:

1. **عزل بعملية Android منفصلة داخل تطبيقنا نفسه** (`:player` process عبر
   Activity Kotlin منفصلة) — وليس تطبيق خارجي. هذا يمنح نفس ضمان "كراش المشغّل
   لا يُسقط التطبيق" لكن بدون فقدان أي ميزة، لأننا نملك الكود بالكامل.
2. **استبدال `expo-video` بـ ExoPlayer (AndroidX Media3) الأصلي مباشرة بـ Kotlin**
   داخل تلك العملية المنفصلة — بدون أي جسر React Native. هذا يزيل مصدر الأخطاء
   الأساسي المشتبه به (تكامل expo-video مع دورة حياة RN)، وليس فقط "استبدال
   مكتبة بمكتبة أخرى داخل نفس العملية" الذي لن يحل مشكلة العزل الجذرية.
3. **الاستفادة من مكوّن UI جاهز مفتوح المصدر مبني على Media3 ExoPlayer** كنقطة
   انطلاق بدل رسم كل عنصر تحكم (إيماءات السطوع/الصوت، شريط التقدّم، عرض
   الترجمة) من الصفر. أفضل مرشح موجود حالياً:
   - **[anilbeesetti/nextplayer](https://github.com/anilbeesetti/nextplayer)**
     — مشغّل أندرويد كامل مبني على Media3 ExoPlayer، Kotlin حديث (Jetpack
     Compose)، مفتوح المصدر (GPL)، نشط الصيانة (+4000 نجمة)، يدعم أصلاً
     إيماءات السطوع/الصوت/الموضع، عرض ترجمة SRT/VTT، تحكّم بالسرعة. يُستخدم
     كمرجع/نقطة انطلاق للواجهة الأصلية (Kotlin) — يُدرَس كوده ويُقتبس منه ما
     يلزم (تُراعى شروط رخصة GPL عند النسخ الحرفي للكود).
   - بدائل أخف إن أردنا نطاقاً أضيق: `eneim/exobase`, `Cxsmo-ai/Just-Another-Skip-Player`.
4. فوق هذا الأساس (عملية معزولة + ExoPlayer أصلي + هيكل UI مُستوحى من
   nextplayer) تُبنى طبقة ميزات NOVA الخاصة: الترجمة الذكية/التلقائية، تخطي
   المقدمة/الخاتمة، مؤقت النوم، تذكّر آخر موضع، تبديل السيرفر بدون إغلاق
   الشاشة، جسر التواصل (bridge) بين عملية `:player` والتطبيق الرئيسي React
   Native (لتمرير الرابط/الترجمة عند الفتح ونتيجة التقدّم عند الإغلاق).
5. **هذا عمل من فئة "أسابيع" فعلاً** (إعادة كتابة واجهة كاملة بـ Kotlin) — تمّت
   الموافقة الصريحة على هذا الحجم من العمل. يُنفَّذ كعمل مخصّص منفصل (راجع
   المهمة المُقترحة)، وليس ضمن مهمة "إعداد المشروع المستورد".
6. يبقى RiftPlayer الحالي (React Native + expo-video) يعمل كخط دفاع أول أثناء
   التطوير، تماماً كما يصف قسم "مسار تدريجي (Rollout)" أدناه، لكن الهدف
   النهائي الآن هو الاستبدال الكامل بالمشغّل المعزول الجديد لا مشغّل خارجي.

## الشريحة الأولى القابلة للاختبار — مُنفَّذة بتاريخ 2026-08-06

كتابة أولى حقيقية (لم تُختبر بعد على جهاز فعلي — تحتاج بناء APK عبر GitHub
Actions، لا يمكن اختبارها داخل Replit):

- **`modules/nova-media3/android/.../IsolatedPlayerActivity.kt`** — Activity
  أندرويد جديدة، مُعلَنة في `AndroidManifest.xml` الخاص بالموديول بـ
  `android:process=":player"` (هذا هو سطر العزل الفعلي). تستخدم ExoPlayer
  مباشرة (لا expo-video)، مع تحكّم Media3 المدمج (تشغيل/إيقاف/تقديم)، ترجمة
  خارجية (VTT عبر `SubtitleConfiguration`)، استئناف الموضع، أزرار تخطي
  مقدمة/خاتمة تظهر ديناميكياً حسب الوقت، ومؤقت نوم اختياري.
- **`NovaMediaSourceFactory.kt`** — منطق بناء `MediaSource` (ترويسات
  Referer/Origin المخصّصة + كشف HLS مقابل ملف مباشر) صار مشتركاً بين
  `NovaMedia3View` (المشغّل الداخلي الحالي) وبين المشغّل المعزول الجديد، بدل
  تكراره.
- **`IsolatedPlayerModule.kt`** — يعرض `NovaIsolatedPlayer.open(config)` عبر
  `AsyncFunction` + `startActivityForResult`/`OnActivityResult` (توثيق Expo
  Modules API الرسمي). يُرجع `{ positionSeconds, durationSeconds, ended,
  crashed }` عند إغلاق المشغّل — بما في ذلك حالة انهيار العملية `:player`
  نفسها (`crashed: true`) بدل رفض الـ Promise، لأن هذا بالضبط الهدف من
  العزل: كراش المشغّل لا يُفسد حالة التطبيق المستدعي.
- **`lib/isolatedPlayer.ts`** — غلاف TypeScript نظيف (`openIsolatedPlayer`)
  للاستدعاء من واجهة React Native.
- **زر اختبار مؤقت** أُضيف داخل `RiftPlayerNative.tsx` (أيقونة ⚗️ في الشريط
  العلوي، أندرويد فقط) يفتح المشغّل المعزول بنفس مصدر/ترجمة/مواضع الحلقة
  الحالية، ويُحدّث موضع RiftPlayer عند الإغلاق. هذا **زر اختبار فقط** وليس
  الافتراضي بعد، تماشياً مع "مسار تدريجي (Rollout)" أعلاه — يُزال أو يُستبدل
  بزر إنتاجي حقيقي بعد إثبات الاستقرار.

## توفير وقت البناء عبر مكتبات جاهزة — قرار مطلوب من المستخدم (2026-08-06)

بدل كتابة واجهة المشغّل المعزول من الصفر، هناك مساران حقيقيان لتوفير الوقت،
لكل منهما ثمن مختلف:

**المسار أ (موصى به — بدون مخاطرة قانونية):** استخدام `PlayerView` المدمج في
مكتبة AndroidX Media3 نفسها (الرخصة Apache-2.0 — نفس رخصة باقي Media3 التي
نعتمد عليها أصلاً). هذا المكوّن **يأتي مجاناً مع ExoPlayer** ويوفّر شريط تحكم
كامل جاهز (تشغيل/إيقاف، تقديم/تأخير، ملء الشاشة) بدون كتابة أي سطر واجهة. فوقه
نضيف فقط ميزات NOVA الخاصة (تخطي مقدمة/خاتمة، مؤقت نوم، استئناف الموضع،
الترجمة الذكية) بترحيل المنطق الموجود أصلاً في `RiftPlayer.tsx` إلى Kotlin —
عمل أقل بكثير من إعادة بناء تطبيق مشغّل كامل، وبدون أي التزام ترخيص إضافي.

**المسار ب (أسرع في البداية لكن يحمل التزاماً قانونياً حقيقياً):** استنساخ كود
[anilbeesetti/nextplayer](https://github.com/anilbeesetti/nextplayer) مباشرة
(الإيماءات الجاهزة للسطوع/الصوت/الموضع + تصميم Compose كامل). المشكلة: رخصته
**GPL-3.0**. دمج كود GPL داخل تطبيق مُوزَّع (APK على المتاجر) يُلزم عادةً
بترخيص **التطبيق بأكمله** تحت GPL أو ما يتوافق معها — وهذا قرار على مستوى
الشركة/المنتج وليس تقنياً بحتاً (يشمل: هل نلتزم بنشر كود Nova بالكامل؟). لا
يجب اتخاذ هذا القرار ضمنياً أثناء التنفيذ.

بدائل أخف مذكورة أعلاه (`eneim/exobase`, `Cxsmo-ai/Just-Another-Skip-Player`)
لم تُتحقّق تراخيصها بعد — يجب فحص كل مكتبة يُراد نسخ كودها فعلياً قبل البدء.

**الخلاصة العملية:** المسار أ يعطي تقريباً نفس النتيجة الوظيفية (مشغّل معزول
بواجهة تحكم كاملة) بجزء من مخاطرة المسار ب، لأن الجزء الأكبر من "إعادة بناء
الواجهة" أصلاً موجود مجاناً داخل Media3 التي نعتمد عليها بالفعل. يُستخدم
نتپلاير (nextplayer) كـ**مرجع قراءة فقط** لفهم كيفية تنفيذ إيماءات معينة
(السطوع/الصوت) دون نسخ كوده حرفياً، ما لم يوافق المستخدم صراحة على المسار ب
وتبعاته.

### غير مُنفَّذ بعد (يبقى ضمن نطاق العمل المتبقي)

- إيماءات السطوع/الصوت المخصّصة (يُعتمد حالياً على تحكّم Media3 الافتراضي).
- الترجمة الذكية/التلقائية (تُدعم فقط الترجمة الجاهزة كملف VTT عبر
  `subtitleUrl`، كما في kawaii).
- اختبار حقيقي على جهاز عبر بناء APK من GitHub Actions — لم يحدث بعد.
- ربط الزر التجريبي بشاشة "watch" الفعلية كخيار مستخدم حقيقي (حالياً داخل
  RiftPlayerNative فقط للتجربة الأولية).

## الخطة الأصلية (تطبيق NOVA Player خارجي) — مرفوضة، مُبقاة للتوثيق التاريخي فقط

**الحالة السابقة:** خطة مكتوبة، لم يبدأ التنفيذ. استُبدلت بالقرار أعلاه.

## لماذا نحتاج هذه الخطة؟

جرّبنا إصلاح كراش المشغّل على مستوى الكود الحالي (RiftPlayer.tsx المبني على
expo-video/ExoPlayer):
- أُصلحت مشكلة تسابق حقيقية (استدعاء `player.replace()` مرتين متزامنتين).
- رغم ذلك، تكرّر خروج التطبيق من أول حلقة عند إعادة فتحه — **قبل** حدوث أي تبديل
  مصدر، ما يعني أن السبب الجذري ليس (فقط) التسابق الذي أصلحناه، بل على الأرجح
  خلل native آخر (تهيئة ExoPlayer، ضغط ذاكرة، أو تعارض مع مكوّن آخر) يصعب اصطياده
  بمراجعة الكود وحدها بدون stack trace حقيقي من الجهاز.

**الخلاصة:** إصلاح الأخطاء واحداً تلو الآخر داخل نفس العملية (process) لن يُعطي
ثقة كاملة، لأن أي كراش native (معروف أو غير معروف) يُسقط التطبيق كله بأكمله.
الحل الوحيد المضمون هندسياً هو أن يعمل التشغيل في عملية Android منفصلة تماماً
بحيث **أي كراش في المشغّل لا يمكنه إسقاط باقي التطبيق مهما كان سببه**.

## القرار: استخدام تطبيق "NOVA Player" المنفصل (الموجود مسبقاً) بدل إعادة الكتابة الأصلية

كان الخيار الأول المطروح ("عزل داخل نفس التطبيق عبر Kotlin Activity على عملية
`:player`") يتطلب عملياً إعادة كتابة كل واجهة المشغّل الحالية (الترجمة،
الإيماءات، شريط التقدّم، الجودة، مؤقت النوم...) بلغة Kotlin أصلية، لأن عملية
منفصلة لا يمكنها مشاركة محرك الجافاسكريبت (React Native) لتشغيل نفس الواجهة.
هذا عمل ضخم جداً (أسابيع).

البديل الأعملي: تطبيق **"NOVA Player"** (الحزمة `com.player.easy`) موجود بالفعل
كتطبيق أندرويد منفصل تماماً — عزل حقيقي جاهز بدون أي إعادة كتابة، لأنه أصلاً
عملية Android مستقلة (APK آخر). نستخدم آلية الإطلاق الموجودة مسبقاً في
`utils/externalPlayer.ts` (تشغيل Intent خارجي) وأصبح هو المشغّل الافتراضي
**لكل** التشغيل بدل RiftPlayer الداخلي.

## نطاق العمل

1. **جرد ميزات RiftPlayer الحالية** التي يعتمد عليها المستخدمون فعلياً (الترجمة
   الذكية/الترجمة العربية التلقائية، تخطي المقدمة/الخاتمة، مؤقت النوم، تذكّر
   آخر موضع مشاهدة، تبديل السيرفر بدون إغلاق الشاشة، تحميل الحلقات) ومطابقتها
   مع ما يدعمه NOVA Player عبر الـ Intent (extras) المتاحة له.
2. **توسيع آلية الإطلاق في `externalPlayer.ts`** لتمرير كل ما يحتاجه NOVA Player
   (رابط الفيديو، الترجمة كملف VTT/SRT إن أمكن، العنوان، رقم الحلقة، موضع
   الاستئناف) وتحديد ما إذا كان يدعم "إعادة التحكم" (رجوع لنفس نقطة عند الرجوع
   للتطبيق، تبديل سيرفر بدون فقدان الموضع).
3. **معالجة الفجوات في الميزات:**
   - إن كان NOVA Player لا يدعم الترجمة الذكية/التلقائية → نحتاج إما (أ) تمرير
     ملف VTT جاهز مسبقاً (نحوّله في تطبيقنا قبل الإطلاق) أو (ب) قبول أن الترجمة
     تعمل فقط للمصادر التي توفّر subtitleUrl جاهزاً (kawaii حالياً).
   - إن كان لا يدعم تخطي مقدمة/خاتمة تلقائياً → نُبقيها ميزة داخل RiftPlayer فقط
     كخيار بديل (fallback) وليس افتراضياً.
4. **تدفّق التبديل بين السيرفرات:** تصميم آلية رجوع (Intent result أو deep-link)
   بحيث لو المستخدم أراد سيرفر آخر من داخل شاشة "watch"، يُغلق NOVA Player
   ويُعاد فتحه بالسيرفر الجديد من نفس الموضع تلقائياً بدون خطوات يدوية إضافية.
5. **تتبّع التقدّم/السجل:** التأكد أن موضع المشاهدة يُحفَظ في تطبيقنا حتى أثناء
   تشغيل NOVA Player (عبر Intent result عند إغلاقه، أو polling دوري إن كان
   يدعم Broadcast/callback).
6. **مسار تدريجي (Rollout) لتقليل المخاطرة:**
   - المرحلة أ: زر "افتح في NOVA Player" اختياري بجانب المشغّل الداخلي (لا نُلغي
     RiftPlayer فوراً).
   - المرحلة ب: لو ثبت استقراره فعلياً على أجهزة حقيقية لعدة أيام/أسابيع →
     يصبح هو الافتراضي، ويبقى RiftPlayer الداخلي بديلاً احتياطياً فقط.
   - المرحلة ج (اختيارية لاحقاً): إزالة الاعتماد الكلي على RiftPlayer إن ثبتت
     الجدوى الكاملة.
7. **بناء واختبار:** كل تغيير يُختبَر عبر بناء APK من GitHub Actions (لا يمكن
   اختباره داخل Replit) وتجربته على جهاز حقيقي فعلي، تماماً كما جرى سابقاً.

## مخاطر معروفة يجب تقييمها قبل البدء

- NOVA Player قد لا يدعم كل صيغ الروابط (headers مخصّصة/Referer/Origin) التي
  يحتاجها proxy الفيديو الحالي — يجب التحقق أولاً بروابط حقيقية.
- تجربة المستخدم ستتغيّر (الانتقال بين تطبيقين بدل شاشة واحدة) — يحتاج قبولاً
  من المستخدم بعد رؤية أول نسخة تجريبية.
- فقدان بعض الميزات المخصّصة (تصميم الترجمة، الإيماءات المخصّصة) ما لم يوفّرها
  NOVA Player بنفس الجودة.

## الحالة الحالية للإصلاحات الجارية (بالتوازي مع هذه الخطة)

بينما نُقرِّر مصير هذه الخطة، استمر العمل على تحسين استقرار RiftPlayer الحالي
كخط دفاع أول (راجع `replit.md`/سجل التغييرات لتفاصيل كل إصلاح لحظي):
- قفل يمنع استدعاء `player.replace()` مرتين متزامنتين.

  توقّفاً حقيقياً.
- محاولة "نقرة" إنعاش تلقائية صامتة قبل الاستسلام والقفز لمصدر بديل.
